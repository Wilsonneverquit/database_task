# 项目工作流程图（数据流 · 库表关系）· 纯表级大字版

一张 **A2 横向（594×420mm）** 的总图，回答三个问题：**数据怎么流、表怎么连、闭环怎么回**。
内容来自 `sql/risk_alert_示例库.sql` 与 `explain.md`；表名、库归属、行数由脚本从建库脚本抽取，不是手抄。

## 二、这一版的设计：卡片只讲三件事

每张卡片 = **表名 + 中文名 + 一句话解释**（右上角小字是示例库行数），不再列字段。

| 元素 | 字号 | 说明 |
| --- | --- | --- |
| 总标题 | 18 pt | |
| 主线 / 这是什么 | 8.2 / 7.0 pt | |
| **库名（① 案例库 色块）** | **11 pt 加粗** | 五个色块＝五个库 |
| **表名** | **19 pt（案例/信息）、18 pt（特征）、21 pt（线索）、11.5 pt（支撑）** | 等宽加粗；**按卡片宽度自动求最大字号**，长表名自动降档，绝不越界 |
| 中文名 | 表名 × 0.74 | 同色，和表名一起读 |
| 一句话解释 | 表名 × 0.56，最长两行 | 自动换行；两行时按“长度最接近 + 断在标点后”切分，避免单字掉行 |
| 流程说明（① 流水、② 统计提炼…） | 7.4 pt | 箭头上的白底标签 |
| 闭环说明 | 7.6 pt 加粗 | 珊瑚色两条回流线 |
| 图例 / 时间轴 | 6.6 / 7.8 pt | |

字号不是拍脑袋给的：`fit()` 先按「可用宽度 ÷ 字符宽度」算出该表名能放多大，
`card()` 再按「表名 + 中文名 + 解释行」的总高度校验，放不下就按 6% 递减重算，所以**不会越界、不会变形**。

## 三、怎么读这张图（30 秒版）

1. **左上到右的箭头**：① 数据接入（案例库 + 信息库）→ ② 统计提炼（P1/P0）→ ③ 版本发布 → ④ 研判执行 → ⑤ 人工核查 → ⑥ 评估滚动。
2. **颜色分库**：蓝＝案例库、紫＝特征库、青＝信息库、橙＝研判线索库、灰＝安全支撑库。
3. **两张视图**：`v_case_history` 画成卡（时点边界唯一出口）；`v_region_risk`、`v_clue_list` 标在线索库库头。
4. **两条珊瑚色粗线**：闭环 A（核查否定的特征 → 扣 hit → 重算 p1/lift → 升版权重）、闭环 B（评估完成 → 观察段并入 case_info → cutoff 右移）。
5. **底部**：全库唯一时间轴 + 图例 + 三条必守。

## 五、怎么改

**改文字最省事**：draw.io 打开 `.drawio`，双击任意文字改；拖动卡片会带着整块内容走。

**重新出图**：

```powershell
cd 项目工作流程图
python extract_schema.py   # sql → schema.json
python build_svg.py        # → 项目工作流程图.svg（含 scene.json）
python render.py           # svg → png(300dpi) + pdf(A2 矢量)
python build_drawio.py     # scene.json → 项目工作流程图.drawio
```

- 每张表的「中文名 / 行数 / 一句话」在 `build_svg.py` 顶部的 `T` 字典；
- 库名、角色、配色在 `G`；版面坐标在 `BOX` 与 `build()`；字号上限在 `card()` 里的 `cap`。
- 渲染用 PyMuPDF（`fitz`）：本机沙箱里 Chrome headless 起不来（命名管道被拦）。

## 七、直接可用的文字

**图注**
> 图 X 项目数据流与库表关系总图。案例库只存历史段案件，经统计提炼为特征库的权重与阈值；研判引擎用特征库口径扫描信息库流水，
> 结果写入研判线索库；核查结论经触发器推进线索状态、经明细表定位被否定的特征，回写下一轮权重；评估标签只在最后一步参与混淆矩阵。
> 全库以 `param_config.history_cutoff` 为唯一时点，观察段并入案例库后自动滚入下一轮。

**答辩 30 秒话术**
> 从左到右是数据流：案例库出经验，特征库存经验，信息库被经验扫描，线索库存结果，评估给答案。
> 两条珊瑚线是闭环：核查否定哪条特征，就回写那条特征的命中数、升一版权重；评估完成后观察段并入案例库、时间点右移。
> 灰色那条是安全支撑库，横切所有库，只提供“谁做的”和“按什么口径”，不反向引用业务数据。
